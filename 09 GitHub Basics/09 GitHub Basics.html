Key Words — Check Off When Explained

⬜
Git
A tool that tracks every change you make to code — like an undo history that never expires, even across a whole team.
GitHub
A website that stores your Git repository online so the whole team can access it from any computer.
Repository (Repo)
The folder that holds your project AND its complete history of every change ever saved.
Commit
A saved snapshot of your changes with a message describing what you did. Think: save + label.
Push
Upload your local commits to GitHub so teammates can see them.
Pull
Download your teammates' commits from GitHub into your local copy.
Clone
Make a full local copy of a GitHub repository on your computer for the first time.
Branch
A separate copy of the code where you can experiment safely — without touching the working main version.
Main
The default branch — the "official" working version of your robot code. You protect it by working on branches first.
Merge
Combine the changes from one branch into another — usually bringing a feature branch back into main.

Clone the Repo & Open in VS Code

⬜

Cloning downloads the full repository — all files AND all history — to your computer for the first time. You only do this once per machine.

Step 1 — Copy the URL from GitHub

On the repo's main page click the green Code button → copy the HTTPS URL. It looks like:
https://github.com/RamRodz6366/RamRodz2025Robot.git

Step 2 — Clone via VS Code (easiest way)

Press Ctrl+Shift+P to open the Command Palette → type Git: Clone → paste the URL → choose where to save it on your computer.

Step 3 — Open the repo in VS Code

After the clone finishes, VS Code shows a pop-up: "Would you like to open the cloned repository?" — click Open. The repo is now your workspace and Git is already connected.

💬 Plain English: Cloning is like downloading a ZIP of all the code, but smarter — it also brings the entire commit history and keeps the link to GitHub so every future push and pull works automatically.
VS Code Source Control Panel — After opening the cloned folder in VS Code, click the branch icon in the left sidebar (or press Ctrl+Shift+G) to open the Source Control panel. This is where you stage, commit, push and pull without typing terminal commands.

Step A — Open Source Control to see changes

Press Ctrl+Shift+G or click the branch icon in the left sidebar. Every modified file appears listed under Changes — you can click any file to see exactly what you edited.

Step B — Stage your files

Hover over a file and click the + icon to stage it, or click the + next to the Changes heading to stage everything at once. Staged files move up to the Staged Changes section.

Step C — Write a commit message and commit

Click the text box at the top of the Source Control panel that says "Message (Ctrl+Enter to commit)". Type a short description — e.g. Add scoreBall() sequence command — then press Ctrl+Enter.

Step D — Push to GitHub

Click the Sync Changes ⟳ button in the Source Control panel — or click the branch indicator in the bottom-left status bar which shows the number of pending commits. One click uploads your commit to GitHub.

💬 Plain English: Think of stage as putting files in a box, commit as sealing the box with a label, and Sync ⟳ as shipping it to the team warehouse on GitHub. Before you start each session, Sync first to pull any boxes your teammates shipped.
⚡ Start of Every Session — Pull First!

Click Sync ⟳ in the Source Control panel before you write a single line of code. This pulls your teammates' latest commits. VS Code shows a notification if anything was pulled. Make it a reflex: open VS Code → click Sync → then start coding.

Good commit messages: Write what you changed and why, not just "fixed stuff". Good: "Add scoreBall() sequence command". Bad: "stuff". Your teammates and future-you will thank you when searching history at 10pm before regionals.

Branches & Merging

⬜

A branch is a parallel copy of your code. You work on the branch without touching main. When it works, you merge it back. If it breaks, you delete the branch and main is still perfect.

Step A — Create a new branch in VS Code

Click the branch name in the bottom-left status bar (it shows main). A menu appears at the top — choose "Create New Branch…", type a name like auto-2025, and press Enter. VS Code automatically switches to your new branch — the status bar updates to show its name.

Step B — Work on the branch and commit

Make your code changes, then use the same Source Control steps you already know: stage with +, write a message, press Ctrl+Enter to commit. Click Sync ⟳ to push the branch to GitHub so your teammate can see it too.

Step C — Switch branches

Click the branch name in the status bar again. All your branches are listed — click one to switch to it instantly. VS Code updates all your open files to match that branch. You can hop between main and auto-2025 as many times as you want.

Step D — Merge back to main when ready

First switch to main via the status bar. Then press Ctrl+Shift+P → type "Git: Merge Branch…" → choose auto-2025. VS Code brings all your branch commits into main. Hit Sync ⟳ to push the merged main to GitHub.

💬 Plain English: Branches are free experiments. Create one, break things, try things. Main stays safe the whole time. When your branch works — merge it in. If it doesn't — delete the branch and walk away. Main never knew.
Branch name in the status bar: The bottom-left corner of VS Code always shows which branch you're on. It's your command center — click it to create a branch, switch branches, or see all branches at a glance. You never need to leave VS Code.
