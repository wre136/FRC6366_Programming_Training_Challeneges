Key Words — Check Off When Explained

⬜
UML
Unified Modeling Language — a standard diagram system for showing how code is structured, like a blueprint before you build
Class Diagram
A UML diagram with three sections: the class name on top, its fields in the middle, and its methods on the bottom
Access Modifier
A keyword that controls who can use a field or method — either public or private in Java
Private ( − )
Only the class itself can read or change this — shown as a minus sign in UML. Used for fields to protect the data
Public ( + )
Any code outside the class can use this — shown as a plus sign in UML. Methods are usually public so others can call them
Subsystem
A class that controls one part of the robot — such as the intake, shooter, climber, or drivetrain

Reading a UML Class Diagram

⬜
ClassName
− fieldName : dataType
− otherField : boolean
+ ClassName()
+ doSomething() : void
+ getValue() : double
  1. 1
    Class Name — the top box. Matches exactly what you type after the class keyword in Java.
  2. 2
    Fields — the middle box. Each − row is a private variable. Format: − name : type
  3. 3
    Methods — the bottom box. Each + row is a public method. The part after the colon is the return type.
💬 Plain English: A UML diagram is a cheat sheet for a class — one glance shows you its name, what data it holds, and what it can do. Engineers draw the diagram before they write the code.

Step by Step — Build IntakeSubsystem

⬜

Here's the UML for our first subsystem. We'll build it one piece at a time — refer back to this diagram at every step.

IntakeSubsystem
− motor       : PWMSparkMax
− rollerSpeed : double
− isRunning   : boolean
+ IntakeSubsystem()
+ run()       : void
+ stop()      : void
+ getSpeed()  : double
+ isActive()  : boolean
🔵 Step A — Class Declaration

The class name comes straight from the top box of the UML.

Java — Step A
class IntakeSubsystem { // name matches the top UML box // fields, constructor, and methods go inside here }
💬 Plain English: This line opens the blueprint. Everything inside { } belongs to IntakeSubsystem.
🔵 Step B — Private Fields

Each row in the middle UML box becomes one field declaration. The − symbol maps directly to the private keyword.

Java — Step B
private PWMSparkMax motor; // − motor : PWMSparkMax private double rollerSpeed; // − rollerSpeed : double private boolean isRunning; // − isRunning : boolean
💬 Plain English: private means only IntakeSubsystem's own code can touch these variables. Other classes are locked out — this protects the data from accidental changes.
✏️ Think About It
🔵 Step C — Constructor

The constructor is the first method in the bottom box — same name as the class, no return type. It sets every field to a safe starting value.

Java — Step C
public IntakeSubsystem() { // + IntakeSubsystem() motor = new PWMSparkMax(4); // motor on PWM port 4 rollerSpeed = 0.0; // start stopped isRunning = false; // not running yet }
💬 Plain English: The constructor runs once, the moment you write new IntakeSubsystem(). It makes sure every field starts safe before the match begins.
🔵 Step D — Public Methods

Each remaining UML row becomes a method. The + maps to public. The part after the colon is the return type — void means it returns nothing.

Java — Step D
public void run() { // + run() : void rollerSpeed = 0.65; // 65% power isRunning = true; // mark active motor.set(rollerSpeed); // send speed to motor } public void stop() { // + stop() : void rollerSpeed = 0.0; // zero the speed isRunning = false; // mark inactive motor.set(0.0); // cut power } public double getSpeed() { // + getSpeed() : double return rollerSpeed; // give back current speed } public boolean isActive() { // + isActive() : boolean return isRunning; // give back true / false }
💬 Plain English: Methods with void do something (run, stop). Methods with a return type like double or boolean give something back to whoever called them.

🎯 Robot Scenario — Build ClimberSubsystem on Your Own

⬜
End-Game Situation

With 20 seconds left your driver presses a button to deploy the climber. The arm must extend to a target position, then retract safely when done. Your coach needs a way to check from outside the class whether the climber is still deployed.

  • The arm is driven by a PWMSparkMax on PWM port 6
  • Track the arm's position (double) and whether it's out (boolean)
  • deploy(position) takes a double parameter — extend to that position
  • retract() brings the arm back to 0.0 and marks it not deployed
  • isDeployed() returns the current deployed state
ClimberSubsystem
− armMotor    : PWMSparkMax
− armPosition : double
− deployed    : boolean
+ ClimberSubsystem()
+ deploy(position : double) : void
+ retract()               : void
+ isDeployed()             : boolean
💡 New this time: deploy(position : double) has a parameter. In Java that becomes public void deploy(double position). Use the parameter like any variable inside the method body — store it in armPosition and pass it to armMotor.set().
✏️ Fields — write all three private field declarations
✏️ Constructor — initialize all three fields (motor on PWM port 6)
✏️ deploy() Method — takes a double parameter named position
✏️ retract() Method — bring the arm home
✏️ isDeployed() Method — returns a boolean
