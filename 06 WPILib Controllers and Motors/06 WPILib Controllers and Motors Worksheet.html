Key Words — Check Off When Explained

⬜
WPILib
The official Java library that FRC teams use to control robot hardware. It gives you ready-made classes for motors, controllers, and sensors.
import
A Java keyword that loads a class from a library into your file so you can use it. Without an import, Java doesn't know the class exists.
XboxController
A WPILib class that represents the Xbox controller plugged into the driver station. You read buttons and joystick axes from it.
Motor Controller
The electronics board between the robot's battery and a motor. Your code tells the motor controller what speed to run, and it handles the power.
PWM
Pulse Width Modulation — a simple signal type used by basic motor controllers. They plug into numbered PWM ports (0–9) on the roboRIO.
CAN Bus
Controller Area Network — a communication system that lets smart motor controllers like the TalonFX talk to the roboRIO over a shared wire loop.

What is WPILib?

⬜
✓
Listen — Instructor explains what WPILib is and why FRC teams use it.

WPILib is a giant toolbox of pre-built Java classes written specifically for FRC robots. Instead of writing code from scratch to talk to a motor or read a joystick, you use WPILib's classes — they handle the low-level electronics for you.

To use a WPILib class in your file, you add an import statement at the very top — one line per class. This tells Java where to find the class definition.

Java — Import Statements
// These lines go at the TOP of your file, before the class declaration import edu.wpi.first.wpilibj.XboxController; // driver controller import edu.wpi.first.wpilibj.motorcontrol.PWMSparkMax; // PWM motor controller import com.ctre.phoenix6.hardware.TalonFX; // CAN motor controller
💬 Plain English: import tells Java "I need that class — go find it in the library." Without the import, Java sees XboxController and has no idea what it is. Every WPILib class you use needs its own import line at the top.
Anatomy of an Import Statement
import edu.wpi.first.wpilibj.XboxController; ↑ ↑ ↑ keyword package path class name

The XboxController

⬜
✓
Listen — Instructor explains how to create an XboxController object and read from it.

An XboxController is a WPILib class that represents the physical Xbox controller plugged into the driver station. You create one object — then call its methods to read button presses and joystick positions.

The constructor takes one number: the port the controller is connected to on the driver station (0 for the first controller, 1 for the second).

Java — Creating and Reading an XboxController
// Declare the controller as a field (inside the class, outside any method) XboxController controller = new XboxController(0); // port 0 = driver controller // ── Inside a method (like teleopPeriodic) ────────────────────────────── // Read the left joystick's Y axis (push forward = negative, pull back = positive) double stickValue = controller.getLeftY(); // returns -1.0 to 1.0 // Read whether the A button is currently held down boolean aPressed = controller.getAButton(); // true if pressed, false if not // Read the right joystick's Y axis double rightStick = controller.getRightY(); // returns -1.0 to 1.0
💬 Plain English: Joystick axes return a decimal from -1.0 (full one direction) to 1.0 (full the other). At rest they return 0.0. Buttons return true when held and false when released. You can feed those values straight into a motor.

Driving a Motor — PWMSparkMax

⬜
✓
Listen — Instructor explains PWM motor controllers and shows how .set() works.
⚡
PWMSparkMax
The SPARK MAX (by REV Robotics) is one of the most common motor controllers in FRC. When wired to a PWM port on the roboRIO, you control it with WPILib's PWMSparkMax class. The constructor takes the PWM port number (printed on the roboRIO, 0–9).
Java — Creating and Using a PWMSparkMax
// Declare as a field — inside the class, outside any method PWMSparkMax driveMotor = new PWMSparkMax(0); // connected to PWM port 0 // ── Inside teleopPeriodic ────────────────────────────────────────────── // Set the motor to 50% forward power driveMotor.set(0.5); // Set the motor to full reverse driveMotor.set(-1.0); // Stop the motor driveMotor.set(0.0);
💬 Plain English: .set() takes a number from -1.0 to 1.0. Positive = forward, negative = reverse, zero = stop. Pass it directly the value you read from a joystick axis and the motor follows the stick.

Connecting the controller to the motor — this is the key pattern:

Java — Controller → Motor (the full data flow)
XboxController driver = new XboxController(0); // controller on port 0 PWMSparkMax leftDrive = new PWMSparkMax(0); // motor on PWM port 0 // ── Called repeatedly during teleop ─────────────────────────────────── double speed = driver.getLeftY(); // 1. read the stick (-1.0 to 1.0) leftDrive.set(speed); // 2. send that value straight to the motor
💬 Plain English: Two lines — read, then send. The joystick axis already returns -1.0 to 1.0, which is exactly what .set() expects. No math needed. Push the stick forward, the motor spins forward. Pull back, it reverses.

The TalonFX — CAN Bus Motors

⬜
✓
Listen — Instructor explains what CAN bus is and how TalonFX differs from PWMSparkMax.
🔧
TalonFX (CTRE)
The TalonFX motor controller is built into the Falcon 500 and Kraken X60 motors — two of the most powerful motors used in FRC. Unlike PWM controllers, the TalonFX communicates over the CAN bus and is programmed using CTRE's Phoenix 6 vendor library, which you add to your project separately from WPILib.

PWM vs CAN — what's the difference?

PWM (PWMSparkMax)CAN Bus (TalonFX)
ConnectionPWM port on roboRIO (wire per motor)CAN bus loop shared by all CAN devices
IdentifierPort number (0–9)Device ID (set in Phoenix Tuner)
LibraryWPILib (built-in)Phoenix 6 (vendor library, added separately)
FeaturesBasic speed controlAdvanced control, position, velocity, current limits
Java — Importing and Creating a TalonFX
// Phoenix 6 import — requires the Phoenix 6 vendor library in your project import com.ctre.phoenix6.hardware.TalonFX; // ── Inside your robot class ──────────────────────────────────────────── // The TalonFX constructor takes a device ID — NOT a PWM port number // Device IDs are configured in Phoenix Tuner X software TalonFX shooterMotor = new TalonFX(1); // device ID 1 on the CAN bus
💬 Plain English: Creating a TalonFX looks just like creating a PWMSparkMax — new ClassName(id) — but the number is a CAN device ID, not a port. Device IDs are set using a tool called Phoenix Tuner X, which talks to the motor controller over USB or the network. The full Phoenix 6 API for controlling the motor is a future lesson — for now, focus on creating the object correctly.
💡 Why does the device ID matter? Every device on the CAN bus shares the same two wires. The device ID is how the roboRIO tells one TalonFX from another. If two devices share the same ID, your robot won't behave predictably. Always verify device IDs in Phoenix Tuner X before running code.
